# Client parity and validation

GUI and CLI invoke one Service and core admission/transaction path. The table
names executable entry points; platform/hardware qualification is recorded
separately and is not implied by route presence.

| Capability | Desktop GUI | CLI | Core / failure evidence |
| --- | --- | --- | --- |
| Names, rooms, registry | Devices | devices | Registry strict import; labels grant no authority |
| Signed local/GitHub release | Settings → Updates | releases | schemas1/2/3 and 20 shared Python/Kotlin package vectors |
| Multi-asset discovery | Check latest | releases latest | explicit firmware role/name/hash; duplicate assets rejected |
| Authenticated BLE update | Review Bluetooth update | updates | identity changes, wrong images, one-use review, reset uncertainty |
| Interrupted BLE upload | Activity review | updates resume | same session and fresh journal/identity review; no auto restart |
| Legacy recovery preparation | Tools | updates prepare | signed shared MIGRATION; no MAIN before identity adoption |
| Single-device candidate trial | Tools → Bluetooth trial | trial | original signed candidate; all pending flags false; isolated admission |
| Durable activity and Stop | Activity / persistent Stop | sessions / interrupt | SQLite intents, no restored consent, interrupted-state retention |
| Double original/export/reopen | Tools | backup | synthetic shared original and changed export rejection |
| First installation | Tools | first-install | bounded pages, UICR preservation, anchor-last full readback |
| Explicit repair/start | Tools / Activity | repair / start | interrupted boundaries, unknown page rejection, separate start review |
| Recovery history/report | Devices / Tools | diagnostics | explicit authenticated read and private export |
| MQTT broker and topics | Settings → MQTT | mqtt | OS store only; explicit plaintext consent; actual disposable broker |
| Zigbee OTA | Devices | zigbee | signed carrier, advancing sample, correlated response, durable network hold |
| Fleet organization | Devices batch / Activity | fleet | mixed saved routes, sequential or network-parallel scheduling, partial outcomes and fresh paused-batch review |
| Appearance | Settings | settings | native light/dark/system palette and keyboard focus test |

Outstanding qualification must remain visible: all native OS BLE/USB permissions,
probe drivers, live watchdog/start behavior and the thirteen firmware physical
checks need real hardware evidence. The shared golden corpus establishes parser
agreement; it is not a substitute for these checks.
